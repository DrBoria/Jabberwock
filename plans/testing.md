## РАЗДЕЛЕНИЕ ИНСТРУМЕНТОВ ПО ПОВЕРХНОСТЯМ

| Поверхность | DOM / скриншот / клики                                                                       | Store                                    | Логи                                                    |
| ----------- | -------------------------------------------------------------------------------------------- | ---------------------------------------- | ------------------------------------------------------- |
| **VS Code** | devtool: `find_element`, `get_screenshot`, `click_element`, `type_in_page`                   | `get_store_state env="backend"`          | `get_diagnostics_snapshot`, `get_console env="backend"` |
| **Web**     | **браузерные** (Playwright): `read_page`, `click_element`, `type_in_page`, `screenshot_page` | `get_store_state env="backend"` (тот же) | `get_console env="backend"`                             |

**Правило разделения:**

- devtool DOM-запросы **broadcast'ят** всем WS-клиентам на :3000.
- Тестируем **VS Code** → браузер на about:blank (НЕ подключён к WS) → devtool видит только VS Code.
- Тестируем **Web** → браузер на `http://127.0.0.1:3000/` → используем **браузерные** (Playwright) инструменты, НЕ devtool.
- Backend store — единый, читается независимо от обеих поверхностей.
- Никогда не используем devtool для Web и Playwright для VS Code.

**Называем поверхности: "VS Code" и "Web"** (не "webview", не "браузер").
